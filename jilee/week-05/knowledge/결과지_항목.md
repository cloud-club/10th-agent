# 리드 결과지 항목 (회의로 채워야 하는 고객정보)

화면설계 「리드 결과지 · 고객 니즈 확인」과 「추진 전환」에서 회의로 채워지는 항목이다. Week 4까지 쓰던 표준 질문 Q01~Q11을 이 틀로 다시 짰다. 에이전트는 회의마다 새로 알게 된 것과 바뀐 것을 `update_result_sheet`로 반영한다.

## 확정 항목 10개 (추진 전환 판정에 센다)

| 코드 | 묶음 | 항목 | 무엇을 적는가 | 확보 기준 |
| --- | --- | --- | --- | --- |
| S1 | 고객 상황 파악 | 현행 운영 방식 | 고객이 지금 어떻게 운영하고 있는가 | 고객이 말한 현재 방식이 구체적으로 적혀 있다 |
| S2 | 고객 상황 파악 | 주요 이슈 | 고객이 불편을 느끼는 지점 | 고객의 표현으로 불편이 적혀 있다 |
| S3 | 고객 상황 파악 | 비즈니스 목표 | 풀리면 무엇이 좋아지는가 | 목표가 한 건 이상 있고, 가능하면 현재 수준과 희망 수준이 있다 |
| S4 | 고객 상황 파악 | 핵심 요구사항 | 요구사항 · 고객배경 · 당사 대응 · 확인 상태 | 요구사항이 한 건 이상 있다 |
| D1 | 의사결정 조직 | 최종 결재자 | 누가 최종으로 결정하는가 | 역할 "의사결정자"가 붙은 사람이 있다 |
| D2 | 의사결정 조직 | 계약 담당자 | 계약·구매 실무를 누가 맡는가 | 역할 "법무·계약" 또는 "구매"가 붙은 사람이 있다 |
| B1 | 구매 가능성 판단 | 예산 상태 | 확보·미확보·확인 불가와 출처 | 상태와 확인 경로가 적혀 있다 |
| B2 | 구매 가능성 판단 | 사업예산·예상 수주금액 | 고객의 총 사업예산과 우리 몫 | 금액이 숫자로 적혀 있다 |
| B3 | 구매 가능성 판단 | 긴급도·착수 희망시기 | 얼마나 급한가 | 긴급도와 그 근거가 되는 고객 일정이 있다 |
| B4 | 구매 가능성 판단 | 계약 예상시기 | 계약을 언제쯤 맺을 수 있는가 | 시기가 월 또는 분기로 적혀 있다 |

참고 항목 X1 경쟁 상황(경쟁사·기존 공급사와 확인 경로)은 함께 쌓되 10개에는 넣지 않는다. 화면설계의 결과지에는 없지만, 수주 가능성을 가리는 데 필요하므로 남겨 두었다.

## 이해관계자의 영업상 역할

의사결정자 · 영향자 · 구매 · 기술 평가자 · 챔피언 · 사용자 · 게이트키퍼 · 법무·계약

한 사람이 여러 역할을 가질 수 있다. 역할은 회의에서 드러난 발언을 근거로 붙인다. 직위만 보고 짐작해서 붙이지 않는다.

## 요구사항의 확인 상태

- 합의됨: 고객과 우리가 범위와 대응에 뜻을 같이했다
- 검토 중: 우리 대응을 내놓았고 고객이 따져 보는 중이다
- 확인 필요: 요구는 나왔지만 대응이 정해지지 않았거나 고객 뜻이 분명하지 않다

## 고객 프로필 (프로젝트와 무관한 고객 단위 사실)

생산품 · 주요 설비 · 기존 시스템. 회의에서 드러나면 `customer_profile`로 적는다. 같은 고객의 다른 프로젝트에서도 그대로 쓴다.

## 상태 규칙

1. AI가 채운 값은 **초안**이다. 사람이 화면에서 확인해야 **확정**이 되고, 확정된 것만 10개에 센다.
2. 모든 값에는 근거 발화가 붙는다. 근거는 이번 녹취의 실제 발언과 맞아야 받는다.
3. 확정된 값이 이후 회의에서 바뀌면 다시 초안으로 돌아가고, 앞 값이 함께 남는다(번복 표시).
4. 추정으로 채우지 않는다. 회의에서 나오지 않은 항목은 비워 두고, 다음 회의에서 물을 질문을 `next_questions`에 적는다.
